# 民泊インタビューの控えメール

## 送るものとタイミング

- 受信希望を選んだ利用者が「確認して完了」を押した時だけ、今回の会話全文と本人確認済みの最終コメントを送る。
- 過去の完了済みインタビューは送らない。活動・イベント案内の同意も利用しない。
- Googleでログインした本人の確認済みメールアドレスだけに送る。Gmailを操作する権限は不要。
- 世田谷区への自動提出はしない。メールにも公式提出先を案内する。
- アプリの「送信受付」はResend APIの受付を意味する。受信箱への到着保証ではない。

## 本番公開前の設定

1. [Resend](https://resend.com/domains) で `mail.civictech-setagaya.org` を送信用ドメインとして追加する。
2. Resendに表示されたDNSレコードを、ドメインを管理しているサービスへ登録する。既存メール用レコードを削除・置換しない。必要な値は[ドメイン認証の公式手順](https://resend.com/docs/dashboard/domains/introduction)とResend画面で確認する。
3. ドメインが認証済みになったことを確認する。開封追跡・クリック追跡は無効にする。送信時はみらい議会のHTML本文と、同じ内容のプレーンテキスト本文を同時に渡す。
4. 送信専用・対象ドメイン限定のAPIキーを発行する。キーはチャット、Git、公開環境変数へ貼らない。
5. Vercelの対象プロジェクトへ、次のサーバー側環境変数を設定する。

| 環境変数 | 値 |
| --- | --- |
| `RESEND_API_KEY` | Resendで発行した送信キー |
| `PUBLIC_COMMENT_RECEIPT_FROM` | `みらい議会＠世田谷区 <noreply@mail.civictech-setagaya.org>` |
| `PUBLIC_COMMENT_RECEIPT_EMAIL_ENABLED` | `true` |
| `PUBLIC_COMMENT_RECEIPT_TEST_EMAIL` | 本番以外で実送信を確認する場合の確認用アドレス1件 |

通常のローカル開発と自動テストは `PUBLIC_COMMENT_RECEIPT_EMAIL_ENABLED=false` とし、実メールを送らない。本番以外の実送信は指定した確認用宛先だけに制限する。`noreply` アドレスへの返信受付は実装していない。

## マージ・デプロイ

- このPRのDBマイグレーションは、既存の `Migrate DB then Deploy` ワークフローが先に適用し、その後Vercelのデプロイを開始する。
- Supabase SQL Editorへの手動貼り付けは不要。重複適用しない。
- 認証とキー設定が済むまでマージを待つ。先に公開した場合も下書き保存はできるが、メールは失敗として表示される。
- 環境変数変更後は再デプロイする。GitHub Actions成功に加えて、VercelがReadyになったことを確認する。
- 指定した確認用Googleアカウントで1回完了し、受信箱の本文・会話順序・最終編集内容・公式リンクを確認する。チェックを外した場合に送らないことも確認する。

## 障害時

- 下書き保存とメール送信を分離しているため、送信失敗でインタビューの完了は取り消されない。
- 完了画面からメールだけを再試行できる。連続送信をサーバーで制限し、同じ本文・宛先・送信元・冪等キーで再試行する。
- 自動バックグラウンド配信や配信対象の一括処理は行わない。画面を閉じた利用者への運営対応には送信記録を確認する。
- 初回送信試行から23時間経過、再試行上限、または結果に矛盾がある場合は運営確認とする。[Resendの重複防止期限は24時間](https://resend.com/docs/dashboard/emails/idempotency-keys)。新しいキーへ差し替えて無条件に再送しない。
- 運営は送信記録の状態・ResendメールIDを使って確認する。メール本文・宛先・会話内容を通常ログ、PR、エラーレポートに貼らない。
- 送信記録はRLSでブラウザから遮断する。個人情報の削除対応では会話と送信記録を合わせて扱い、Resend側に残る配信データも確認する。

## 確認範囲

単体テストはResendをFakeに置き換え、DBの権限・完了トランザクション・重複防止・期限・本文の固定はローカルSupabaseの統合テストで確認する。実際のGoogleログイン、PC・スマートフォンのブラウザ表示、本番メール受信は別途確認する。
